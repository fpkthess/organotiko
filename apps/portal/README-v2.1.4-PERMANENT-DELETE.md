# PROTOPORIA PORTAL v2.1.4 — Οριστική διαγραφή εσόδου / εξόδου

## Τι προστέθηκε

Στην καρτέλα **Οικονομικά → Έσοδα / Έξοδα**, κάθε εγγραφή έχει πλέον κόκκινο κουμπί **Διαγραφή** δίπλα στην **Επεξεργασία**, ορατό μόνο σε Admin. Το κουμπί ανοίγει προσαρμοσμένο παράθυρο με:

- περιγραφή της εγγραφής και προειδοποίηση ότι διαγράφονται **όλες** οι συνδεδεμένες πληρωμές **όλων** των μηνών, όχι μόνο του μήνα που εμφανίζεται στην οθόνη·
- αιτιολογία διαγραφής (5–500 χαρακτήρες)·
- υποχρεωτική πληκτρολόγηση **ΔΙΑΓΡΑΦΗ** πριν επιτραπεί η οριστική πράξη.

Η πράξη εκτελείται σε **μία ατομική RPC συναλλαγή** `finance_delete_register`. Διαγράφει το οικονομικό μητρώο, τις πληρωμές του, τους αντιλογισμούς, τις επιμέρους κινήσεις λογαριασμών, τους επιμερισμούς εκδηλώσεων και τις αντίστοιχες αναφορές εισαγωγής ιστορικών αρχείων (όταν επιτρέπεται από τα κλειδώματα). Τα διαθέσιμα και οι οικονομικές αναφορές υπολογίζονται εκ νέου από τις εναπομείνασες κινήσεις. Διατηρείται **πλήρες snapshot σε finance_audit** για λογιστική ιχνηλασιμότητα.

**Η διαγραφή δεν είναι αντιλογισμός.** Τα πρωτογενή rows διαγράφονται· το audit επιβιώνει.

## Προστασίες

- **Μόνο Admin**· οι άλλοι χρήστες και ανώνυμοι δεν μπορούν να εκτελέσουν τη λειτουργία. Ο έλεγχος είναι στη βάση, όχι μόνο στο κουμπί.
- Εάν η εγγραφή περιλαμβάνει κίνηση σε κλειδωμένο μήνα (ή μεταγενέστερο κλείσιμο), ολόκληρη η διαγραφή απορρίπτεται. Καμία μερική διαγραφή.
- Εάν υπάρχουν συνδεδεμένα **Αναμενόμενα** (συμπεριλαμβανομένων πραγματοποιημένων), η διαγραφή εμποδίζεται για να μη μείνουν σπασμένες συνδέσεις. Τα αναμενόμενα πρέπει να αποσυνδεθούν/τακτοποιηθούν με την ορθή διαδικασία.
- Εάν υπάρχουν **παραστατικά**, η διαγραφή εμποδίζεται· η διαγραφή φυσικών αρχείων γίνεται μόνο από το Supabase Storage API, όχι με SQL. Απαιτείται ξεχωριστή ασφαλής ροή αφαίρεσης παραστατικών.
- Η διαγραφή δεν αγγίζει SMS, χρήστες, εργασίες, εκδηλώσεις, τραπεζικές μεταφορές ή εγγραφές άλλων μητρώων.

## Κατάσταση βάσης

Η νέα migration `finance_permanent_register_delete_v214` **εφαρμόστηκε ήδη** στην παραγωγική Supabase ORGANOSI και δοκιμάστηκε με προσομοιωμένη εγγραφή, 2 πληρωμές και αντιλογισμό, μέσα σε transaction που ολοκληρώθηκε με ROLLBACK. Το αρχείο `supabase/019_finance_permanent_delete_register.sql` είναι για τεκμηρίωση και νέες εγκαταστάσεις. **ΜΗΝ εκτελέσεις 012–019 ξανά στο τρέχον παραγωγικό project.**

Η παραγωγή είχε ήδη κλειδώσει οικονομικούς μήνες έως και τον Σεπτέμβριο 2026 όταν έγινε η νέα αναβάθμιση. Αυτό σημαίνει ότι οι περισσότερες ιστορικές εγγραφές **δεν μπορούν** να διαγραφούν μέχρι να ανοιχτούν νόμιμα οι εμπλεκόμενοι μήνες από Admin.

## Εγκατάσταση Cloudflare — μόνο code deploy

1. Κράτησε αντίγραφο της προηγούμενης έκδοσης. Αποσυμπίεσε το FULL ZIP.
2. Άνοιξε PowerShell μέσα στον φάκελο `PROTOPORIA-PORTAL-v2.1.4` (εκεί όπου είναι `package.json`).
3. Τρέξε:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\RUN-02-DEPLOY-CLOUDFLARE.ps1"
   ```

4. Το script εγκαθιστά εξαρτήσεις, κάνει `tsc` + Vite build και tests και ελέγχει ότι το frontend δείχνει στο **production ORGANOSI**, πριν ζητήσει επιβεβαίωση `DEPLOY PORTAL`. Δες ότι εμφανίζεται ο σωστός λογαριασμός Cloudflare, και προχώρα μόνο αν επιτύχουν όλα τα βήματα.
5. Μετά το deploy άνοιξε **Οικονομικά → Έσοδα / Έξοδα** στον Οκτώβριο 2026, επιβεβαίωσε ότι υπάρχει το κόκκινο κουμπί διαγραφής, άνοιξε/κλείσε το παράθυρο **χωρίς** να διαγράψεις πραγματικό δεδομένο.

Το package **δεν** περιέχει νέα σύνδεση ή κλειδιά αποστολής SMS. Τα υπάρχοντα Cloudflare secrets και τα scheduled SMS πρέπει να μείνουν ανέπαφα. **Μην ξανατρέξεις το RUN-01** ούτε historical import.
