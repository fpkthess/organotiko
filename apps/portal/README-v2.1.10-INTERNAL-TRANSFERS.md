# PROTOPORIA PORTAL v2.1.10 — Internal Transfers

## Τι διορθώθηκε

1. **Πραγματική κατεύθυνση μεταφοράς:** Εμφανίζεται πρώτα ο λογαριασμός με αρνητική λογιστική κίνηση (`delta < 0`) και μετά εκείνος με θετική (`delta > 0`). Δεν χρησιμοποιείται πλέον η αλφαβητική σειρά λογαριασμών.
2. **Μικρό κόκκινο καλάθι διαγραφής:** Στις μεταφορές αντικαταστάθηκε το τεράστιο κουμπί «Αντιλογισμός» από ένα κουμπί μόνο με το εικονίδιο κάδου (38×38 px), δίπλα ή κάτω από το ποσό. Το ποσό δεν σπάει σε γραμμές στο κινητό.
3. **Οριστική διαγραφή μεταφοράς:** Ο Admin επιβεβαιώνει τη διαγραφή. Η Supabase διαγράφει ατομικά την μεταφορά και τις δύο κινήσεις λογαριασμών, τις σχετικές πληροφορίες ιστορικού εισαγωγής και τυχόν συσχετισμένο προηγούμενο αντιλογισμό. Πριν από τη διαγραφή κρατά πλήρες snapshot στο `finance_audit`. Τα υπόλοιπα προκύπτουν εκ νέου από το ledger.
4. **Προστασίες:** Δεν διαγράφονται εγγραφές κλειδωμένων μηνών. Εάν υπάρχουν εξαρτήσεις, η διαγραφή απορρίπτεται χωρίς μερική μεταβολή. Η λειτουργία είναι μόνο για Admin και απορρίπτει anonymous / member χρήστες.
5. **Συντήρηση:** Δεν αλλάζει η διαχείριση εσόδων/εξόδων ή το ιστορικό τους, οι SMS καμπάνιες, ο authentication worker ή οι χρήστες.

## Βάση και εγκατάσταση

Η συνάρτηση **`public.finance_delete_transfer(uuid,text)` έχει ήδη εγκατασταθεί** στο παραγωγικό Supabase ORGANOSI (migration `transfer_permanent_delete_v2110`). **Μην ξανατρέξεις** το SQL από τον φάκελο `supabase/migrations`.

Το SQL περιλαμβάνεται μόνο ως τεκμηρίωση του backend. Το ZIP δεν τρέχει SQL αυτόματα. Εγκατάστησε την έκδοση με το υπάρχον `RUN-02-DEPLOY-CLOUDFLARE.ps1` σε PowerShell — απαιτεί επιτυχημένα npm install, build, tests, επιβεβαίωση Cloudflare πριν από deployment.

Η διαγραφή πραγματικής μεταφοράς πραγματοποιείται **μόνο όταν ο Admin πατήσει τον κάδο** και επιβεβαιώσει. Οι δοκιμές backend έγιναν μέσα σε `BEGIN ... ROLLBACK`, χωρίς μόνιμες δοκιμαστικές εγγραφές.
