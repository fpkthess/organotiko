# Κεντρικό Audit Log — τι καταγράφεται

Ο Audit Log είναι η υπάρχουσα `public.audit_log` του Portal, όχι δεύτερο SMS log.

| Ενότητα | Καταγραφή | Παράδειγμα metadata (όχι μυστικά) |
| --- | --- | --- |
| Λογαριασμοί | Δημιουργία, ενεργοποίηση/απενεργοποίηση, αλλαγή ρόλου, αλλαγή SMS permissions, ιδιότητα | Actor, user ID, old/new role, permission toggles |
| Ασφάλεια | Reset κωδικού από Admin, επιτυχές login/προσωπική αλλαγή κωδικού μέσω Portal | Actor και τύπος γεγονότος, όχι κωδικός |
| Ομάδες | Δημιουργία/επεξεργασία ομάδας, αλλαγές μελών/συντονιστή | Team ID, user ID, access |
| Εργασίες | Δημιουργία/αλλαγή προθεσμίας, priority, status, checklist και αναθέσεις | Task ID, προηγούμενη/νέα κατάσταση, due date, περιγραφή_changed |
| Σχόλια | Δημιουργία σχολίου | Comment ID, όχι περιεχόμενο |
| Εκδηλώσεις | Δημιουργία, αλλαγή τύπου/χώρου/ημερομηνίας, επιβεβαίωση | Old/new program metadata |
| SMS Sender IDs | Προσθήκη, ενεργοποίηση, απενεργοποίηση, αρχειοθέτηση | Sender, old/new enabled |
| SMS εξαιρέσεις | Προσθήκη/αφαίρεση | Τελευταία 4 ψηφία μόνο |
| SMS επαφές | Import APPEND/REPLACE, μεμονωμένη προσθήκη/αφαίρεση | Λίστα, πλήθος εισαγωγής, διπλότυπα, όχι πλήρης αριθμός |
| SMS καμπάνιες | Δημιουργία, ακύρωση μη αποσταλμένων, ολοκλήρωση, εξαγωγή CSV | Πάροχος, Sender, προγραμματισμός, πλήθος, τελική κατάσταση, όχι μήνυμα |
| Σύστημα/Cron | Ολοκλήρωση καμπάνιας μετά από αποστολές, αποτυχίες ή αβεβαιότητα | Actor = system, counts/status |

### Για τις αποστολές ανά αριθμό

Αναλυτικές καταστάσεις, provider message ID, χρόνος επεξεργασίας και περιορισμένη τεχνική σημείωση διατηρούνται στους πίνακες `sms_recipients`, δηλαδή στο **Ιστορικό καμπάνιας**. Ο κεντρικός Audit Log δεν πλημμυρίζει με 1.500 ισοδύναμες εγγραφές για κάθε SMS· καταγράφει τα γεγονότα της καμπάνιας και τις διαχειριστικές πράξεις.

### Προστασία δεδομένων

- Δεν καταγράφονται password, access token, secret, OAuth token, περιεχόμενο SMS και ολόκληρος αριθμός κινητού στο **Audit Log**.
- Το πλήρες μήνυμα, τα πλήρη τηλέφωνα και η κατάσταση ανά αποδέκτη υπάρχουν στις αντίστοιχες SMS οντότητες για λειτουργική χρήση από εξουσιοδοτημένα στελέχη.
- Το Audit Log δεν έχει delete/update policy για browser χρήστες. Η read access ελέγχεται από Admin ή ειδικό `view_audit` δικαίωμα.
- Δεν υπάρχει job αυτόματης διαγραφής μετά από 24 ώρες. Αργότερα πρέπει να οριστεί επίσημη πολιτική retention/GDPR.
- Καταγραφές login/αυτοαλλαγής κωδικού μέσω browser είναι **best effort**. Για πλήρες auth security trail, χρειάζονται ξεχωριστά Supabase Auth logs/webhooks.

### Πότε δημιουργείται υποχρεωτικά καταγραφή

Οι διαχειριστικές SMS αλλαγές (import/εξαιρέσεις/sender/campaign create/cancel) γράφουν Audit **μέσα στην ίδια συναλλαγή PostgreSQL** με την αλλαγή. Αν αποτύχει η εγγραφή, αποτυγχάνει και η μεταβολή. Τα υπόλοιπα Portal triggers συνεχίζουν να γράφουν audit στις DB μεταβολές.
